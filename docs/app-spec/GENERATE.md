# Generated Clips — a Prompt on the Timeline

A clip that is described instead of filmed: a still picture or a few
seconds of video made by a generator model the user runs themselves. It is
the same idea as [web clips](./WEBCLIP.md), [music clips](./MUSIC.md) and
the [person cutout](./CUTOUT.md): the clip carries a description, a job
makes a file, and the file is made again only when the description
changes.

```text
prompt + preset + settings + seed ─► key ─► job on a generator the user runs
      ─► a take: a file in the project ─► the clip plays it like any media
```

**Local first.** NearEdit talks to generators on the user's own machine or
network — ComfyUI, Ollama, or a program of their own. It installs no
models and downloads none. Hosted services can be added behind the same
interface later.

**What works where.** Making *video* needs a real graphics card and takes
minutes for seconds of footage; making a *still* is within reach of far
more machines. So the default a casual user meets is **a generated still
with a slow move over it**; "animate this" and text-to-video appear when a
generator that can do them is connected.

## Two levels, one interface

- **Casual:** a prompt and a length. Shape and frame rate come from the
  timeline; the look can borrow words from the brand kit.
- **Power:** a **preset** — a generator workflow as a file, with a small
  header that says which of its inputs are the prompt, the seed, the size
  and the length, and which further knobs to show. The inspector builds its
  controls from the header. The interface never grows a node editor; the
  tweaking lives in the file.

## In the document

```json
{ "sourceFile": "/project/.nearedit/generate/5d0c….png", "timelineStart": 8, "timelineEnd": 13,
  "generate": { "kind": "image", "prompt": "a foggy pine forest at dawn, wide shot",
                "negative": "", "preset": "still", "settings": {}, "seed": 12345,
                "start": null, "key": "5d0c…",
                "takes": [{ "key": "5d0c…", "file": "/project/.nearedit/generate/5d0c….png",
                            "seed": 12345, "backend": "comfyui", "standIn": false }],
                "take": 0 },
  "credit": { "provider": "generated", "creator": "model name", "license": "…", "generated": true } }
```

- `kind`: `image` or `video`. `start` names a picture to begin from
  (image-to-video).
- **Key**: 20 hex digits of the SHA-256 of everything that decides the
  result — preset and its revision, prompt, negative prompt, settings,
  seed, size, length and frame rate, the start picture's identity.
  `generateKey(...)`.
- **Takes.** Generation is not reproducible from one machine to another,
  so the file is the truth: every result is a take, kept until removed, and
  `take` says which one plays. Asking again with another seed adds a take.
- **Out of date**: the description's key differs from the playing take's.
  Nothing is regenerated by itself — a generation costs minutes — the clip
  says so and waits for **Generate**. The same description never runs
  twice: its take is found.
- **A stand-in from the first moment.** A new generated clip gets a
  stand-in take at once — a card with its prompt — so it can be placed,
  timed and cut around before anything is generated. An export says which
  clips are still stand-ins.
- A generated clip's `credit` (see [STOCK.md](./STOCK.md)) names the model
  and its licence and marks it as generated, so the credits file can carry
  the disclosure platforms ask for.
- Length: a preset says how long a clip it can make; a longer wish gets
  what the preset can do, and the result says so. A still has any length.

## Presets

A folder: `<data>/workflows/<id>/` with `preset.json` and, for ComfyUI, the
workflow exported in API format.

```json
{ "id": "still", "name": "Still picture", "kind": "image", "backend": "comfyui",
  "workflow": "workflow.json",
  "inputs": { "prompt": ["6", "text"], "negative": ["7", "text"], "seed": ["3", "seed"],
              "width": ["5", "width"], "height": ["5", "height"] },
  "output": "9",
  "limits": { "sizes": [[1280, 720], [720, 1280], [1024, 1024]], "multiple": 16, "maxSeconds": 0 },
  "knobs": { "steps": { "input": ["3", "steps"], "type": "number", "min": 1, "max": 50,
                        "default": 20, "label": "Steps" } },
  "model": "name shown in credits", "license": "what the model's licence allows",
  "requires": ["what must be installed in the generator"] }
```

- `inputs` map NearEdit's fields onto the workflow's nodes (`[node id,
  input name]`); video presets add `frames`, `fps` and, for image-to-video,
  `start`. `knobs` are shown in the inspector, generated like effect
  parameters.
- The preset's **revision** (a hash of both files) is part of every key.
- Presets shipped with NearEdit are in `workflows/` of the repository;
  one in the data folder with the same id wins.

## Generators

| Backend | Setting | Makes |
| ------- | ------- | ----- |
| `standin` | — | The stand-in card. Always there |
| `comfyui` | `COMFYUI_URL` | Whatever the preset's workflow makes: stills, video, image-to-video. The workflow is queued over ComfyUI's own interface, its progress followed, its result fetched |
| `ollama` | `OLLAMA_URL` | Stills, where the Ollama installed there has image generation (experimental at the time of writing) |
| `command` | `GENERATE_COMMAND` | A program of the user's: it is given the request as JSON and writes the file |

`GET /generate/status` says which are reachable and what each can make;
the casual default picks the first that can make what was asked, and says
which it picked.

## Server

| Method | Route | Purpose |
| ------ | ----- | ------- |
| GET | `/generate/status` | Backends and presets, what each can make, what is missing |
| POST | `/generate` | `{ projectId, generate, width, height, fps, seconds }` → `202 { jobId }`; job type and lane `generate`, progress as the backend reports it, result `{ file, key, kind, width, height, duration, seed, backend, preset, cached }` |
| POST | `/generate/standin` | The stand-in card for a description, at once |

Files: `<project>/.nearedit/generate/<key>.<ext>` and `<key>.json` (what
it was made from). A cancelled job stops the generator too.

## Finishing it on a real machine

This was built where there is no graphics card: the ComfyUI and Ollama
backends follow their published interfaces and are tested against
stand-ins. [GENERATE-SETUP.md](./GENERATE-SETUP.md) is the checklist for a
machine that has one — connecting, exporting a workflow as a preset,
running the conformance check, and what to look at.

## Limits

- No model is installed or chosen for the user.
- One generation at a time.
- No inpainting, no editing of a take, no upscaling step of its own —
  those belong in a preset's workflow.
- Sound is not generated.
